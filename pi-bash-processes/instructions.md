## pi-background-tasks — `bg_task` and `bg_status`

Model-facing Bash commands are managed from process start. If a command exceeds the foreground wait (20 seconds by default), Bash returns a `Running` task ID and keeps executing in the background. Running is not success: do not use its output or artifacts yet, and continue only work that is independent of the result. Do not poll: no `sleep`/`tail`/`while` monitor loops, and no repeated `list`/`log`/`wait` calls while a task runs. If nothing independent remains, finish the turn with a brief waiting status and go idle; completion (or timeout) wakes you in a new agent turn with the output tail — that wake is the delivery mechanism, not a suggestion.

`bg_task` starts commands in the background immediately; `bg_status` inspects/stops them. Use these instead of `nohup`, `&`, `disown`, or foreground polling loops. `bg_task action: "wait"` blocks for a bounded window (`waitSeconds`, default 30, max 120) and returns the terminal result or a truthful `Running` status; reserve it for the narrow case where this same turn cannot proceed without the result — continuing async is the default, ending the turn is the normal await. Reading a result consumes its pending wake; there is no penalty for looking: `bg_task list` and `pi-bg peek <id>` report status without consuming, while `bg_task log`, `pi-bg read <id>`, and any read of the log through `cat`/`tail`/`head`/`grep`/`less` consume it — you will not be woken for output you have already seen.

Every task also gets a soft reminder (default 10 minutes, `softTimeoutMs` per spawn, 0 disables). A soft wake is not an exit and stops nothing: it reports elapsed time and output and asks the agent to decide — continue (optionally `bg_task action: "extend" id:... softTimeoutMs:...` for a fresh window from now; this never changes the hard timeout), inspect/read the log, or stop. Respond to a soft wake in the same turn if possible; the hard `timeoutSeconds` is only a backstop.

Actions: `spawn`, `list`, `log` (by id/pid), `stop` (accepts `"all"`), `wait`, `clear` (drop finished entries). Before spawning, check the ack's inventory: if an identical command is already running or finished recently, prefer `log`/`wait` on the existing task or fix the cause instead of rerunning; rerun only what changed.

Wakes: exits notify by default (`notifyOnExit`); `notifyOnOutput` + `notifyPattern` wake on matching new output (`notifyMode`: `always` | `transition` | `first-match-only`). `timeoutSeconds` sets a hard runtime limit. Multiple exits in the same window arrive batched; a missed wake (crash, restart) replays exactly once, and stopping a task sends no wake (the stop result is the delivery). Stop turn-scoped tasks you no longer need before finishing the turn.

Resource controls (opt-in setting, off by default): heavy tasks can run through a `systemd-run` transient service or a `nice`/`ionice` fallback while preserving log capture, wakeups, timeouts, and `/bg:stop`.
